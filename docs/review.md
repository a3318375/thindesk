## 本次修复

### Codex JSONL 被 Unicode 分隔符切断

`node:readline` 会把 U+2028／U+2029 当作行边界。这两个字符可以直接出现在合法 JSON 字符串里，因此模型输出此类文本时会触发错误解析并中止回答。

改为 UTF-8 流解码后仅按 LF 切分记录，与现有 Pi RPC／模型目录的 framing 方式一致。新增回归将中文 UTF-8 字符拆到两次 stdout 写入，并在同一条 JSON 中包含两种分隔符，验证最终正文完全保留且轮次完成。

### 正文后缀被误当作停止状态

服务端先前通过 `text.endsWith("已停止生成。")` 判断轮次是否取消。正常回答引用该文本也会被错误标记为中断。

改为从运行器结束通知显式传入 cancelled，正文不再决定执行状态。新增真实 HTTP → 队列 → 运行器替身回归，确认此类正常正文依然是 complete。已有停止／继续测试继续覆盖真正取消路径。

## 后续实施：提问、配置、存储与独立执行

本轮移除了整份 Desk JSON 的热路径读写，新增 DeskStore 的会话／消息表及脏消息跟踪；新增消息和流式变化不重写旧正文，会话摘要按版本缓存。原始 JSON 在首次保存时事务迁移。迁移前需 SQLite backup，旧代码回滚需恢复旧数据库。

执行生命周期移入 turn-worker.ts，生产用独立用户级 systemd 单元，Web 只观察原子快照和投递控制消息。Web 重载可重新连接等待用户回答的同一运行器进程；不重发上一条问题。worker 本身丢失则结束待回答状态并暂停队列，不能宣称机器重启也能恢复原进程。

新增原生提问／审批协议映射、QuestionFlow、逐模型思考滑块及后端校验。Codex 默认模式启用 request_user_input 功能；Pi 自带工具扩展调用现有 RPC UI。核对本机实际模型：Codex 默认模型提供 low 到 ultra，Pi 默认模型提供 off 到 high，两套档位没有统一硬编码。

针对测试：原生提问刷新、允许／拒绝、答案回传、同一 PID 重新接管、过期请求拒绝；分表迁移、增量只写变化消息、复制与删除；档位实传与非法档位拒绝。另用真实用户级 systemd 启动本地运行器替身验证进程分离，并以本机 Pi 无会话 RPC 验证扩展加载；这些不等于各云模型供应商的实机调用回归。

新增已知边界：启动仍预加载历史；运行快照暂按轮保留无自动清理；Pi UI 确认不等同于 Codex 沙箱审批；更全面的 Skills／MCP 配置不在本轮实现范围。


本轮验证结果：构建通过，完整回归 70 项通过。末尾对摘要精简、手机菜单、复制待回答会话和 CLI 默认档位的调整另做定向回归。约 8 MB 历史的本地测试确认 5 次流式更新只更新 5 条消息记录；约 1ms 是该机器该样本的内存数据库结果，不作为任意数据库规模的性能承诺。用户级 systemd worker 的 cgroup 与 Web 服务不同；故障注入后返回明确中断，没有自动重跑。
